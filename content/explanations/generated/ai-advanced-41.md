## 参考回答

<!-- explanation:deep -->

> 场景与约束：网银问答沙盘:单 Agent 准确率 82%,改造成"检索 Agent+分析 Agent+汇总 Agent"后降到 76%——多 Agent 的协调开销、错误传播与上下文割裂,可能吃掉分工的理论收益。

1. 多 Agent 的三种额外成本:上下文割裂(各 Agent 只见局部信息,全局判断没人做)、错误传播(上游 Agent 的错误输出成为下游的事实源,错误被"认证"放大)、协调开销(消息传递+格式对齐+重复理解,token 与延迟双增)。
2. 收益的成立条件:任务可清晰分解+子任务间低耦合+每个子任务有独立价值(可单独评测)——三者不满足时,多 Agent 是把一个上下文里的连续思考切成多次"失忆接力"。
3. 演进路径:先单 Agent+工具(多数场景的天花板比想象高)→单 Agent 到达上下文或工具数瓶颈→再按"信息隔离需求"拆分(拆的依据是上下文隔离,不是职能好看)。

## 参考分析

### 机制:分解是有损的

把任务分给多个 Agent=把上下文切片:每个 Agent 丢失其他片段的细节,综合判断(哪个证据更可信、哪个用户约束优先)在切片里无家可归。汇总 Agent 只能基于二手摘要判断——信息在传递中降级。类比科室会诊:医生各自只看自己科室的检查单,没有医生看全片——分科的前提是"分科不损失关键关联"。

### 反例:多 Agent 的两种事故

事故一:检索 Agent 给分析 Agent 的"top5 文档摘要"丢了矛盾条款——分析 Agent 在残缺事实上推理,输出自信的错误结论(错误被下游"认证");修复=传递原始证据或全链路共享上下文。事故二:三 Agent 链路每跳加一次模型调用——延迟×3、成本×3,而单 Agent 一次调用已够;修复=收益对照驱动拆分,不是架构审美。

### 取舍:单 Agent、流水线与真多 Agent

单 Agent+工具:默认形态(上下文全量,无传递损耗);流水线(固定步骤多模型):步骤间转换是确定性的(检索→重排→生成是流水线不是 Agent),不算多 Agent;真多 Agent(动态协作):信息隔离有明确收益时(隔离不可信内容,第 40 题;或并行探索广度)才用——按收益证据演进,不为架构图好看。

## 案例

### 验证:单多 Agent 的对照核对

推演核对(教学示例):同评测集三形态——单 Agent+工具/两 Agent 流水线(检索+回答)/三 Agent 协作(检索+分析+汇总)——对照准确率、延迟、token 成本。预期:流水线接近单 Agent(转换确定性),三 Agent 协作因上下文割裂准确率下降、成本上升。验证:三形态同框数据即架构决策依据;单 Agent 的"天花板"要先测(工具数与上下文余量),没测到瓶颈不拆分。

### 追问链:多 Agent 三刀

一刀:"什么时候多 Agent 真有收益?"——并行探索(多假设同时验证)、隔离(不可信内容的执行隔离,第 40 题)、长任务分档(上下文真装不下)——三类收益明确才拆。二刀:"拆了之后信息怎么补?"——关键全局信息(用户约束/已确认事实)显式共享(共享黑板结构),不靠 Agent 间转述。三刀:"子 Agent 的评测?"——每个子 Agent 单独评测(第 1 题分层)+链路整体评测,双层都要;只测整体找不到该优化哪段。

## 总结点

1. 分解是有损的,割裂吃掉收益
2. 先测单 Agent 天花板再拆
3. 拆分依据=信息隔离需求
