# 每道题的 AI 与 RAG

AI 学习助手位于题目详情下方，支持解释题目、生成参考回答、常见追问、自定义问答。展开知识来源可以查看本次检索片段。管理员可点击“编辑并保存为回答”，进入原有 Markdown 编辑流程，手动保存才会更新题库；普通账号只能问答和查看。

## 配置
在部署目录 .env 增加：
```dotenv
AI_ENABLED=true
AI_BASE_URL=https://你的服务地址/v1
AI_API_KEY=你的密钥
AI_MODEL=服务商提供的聊天模型名
AI_EMBEDDING_MODEL=服务商提供的向量模型名
```
AI_EMBEDDING_MODEL 可留空，使用关键词 RAG。然后运行：
```sh
docker compose up -d --build backend web
```
密钥仅由后端读取，不会返回浏览器。模型支持兼容 OpenAI 的 /chat/completions 接口；向量模型需支持 /embeddings 与浮点向量格式。聊天和向量目前共用一个接口地址及密钥。

Ollama 使用 http://可访问的Ollama主机:11434/v1，密钥可空，模型需先安装。在容器内 localhost 指向容器自身，请使用可达的主机地址。

协议依据：[Chat Completions](https://developers.openai.com/api/reference/resources/chat)、[Embeddings](https://developers.openai.com/api/reference/resources/embeddings/methods/create)、[Ollama 兼容接口](https://docs.ollama.com/api/openai-compatibility)。

## 知识库
管理员进入“AI 知识库”上传 UTF-8 Markdown/TXT。每份最多 1.5MB、50 万字符，最多 50 份。已有有效题目及独立参考资料自动同步，题目修改或删除后下次检索更新。原 Java.md 不改写。原始导入资料保留用于历史查看，但其中编号题目及旧答案不再重复进入检索，避免题库修改/删除后从原文副本召回旧内容；上传的独立资料不受这一过滤影响。

页面分为“检索资料”“知识来源”“服务设置”。默认先查资料；知识来源按题库题目、参考资料和上传文档分类，支持名称筛选、分页和完整原文预览。上传列表为空不代表知识库为空。来源预览只读，题目可在新标签页打开；题目或所属模块归档后不可继续预览。模型配置说明和向量构建集中在服务设置中。

资料按约 1000 字符切分，重叠 120 字符，保存在 MySQL/H2 的 ai_chunks 表。默认使用英文词和中文双字词的 BM25 检索。填写向量模型后，在服务设置点击“构建一批索引”，每次最多 16 片段；重复直到剩余为零。构建会调用配置的模型服务，按该服务计费。问答使用 BM25 和余弦相似度混合排序，最多带入 6 个片段。新资料及题目更新后仍可立即使用关键词检索，向量需再构建；更换接口或向量模型后旧向量不参与检索。

“检索资料”只做关键词检索，不调用模型；结果按来源分组，支持查看命中片段及完整资料，摘要去除 HTML 和 Markdown 标记。启动后首次使用会核对索引，后续在内容事务提交后按来源增量更新；状态读取不再扫描所有题目。检索缓存不可变的分词/倒排快照，内容版本变化后重建，普通查询复用；不再每次全量读取和分词，也不再静默截断为前 20000 个片段。向量仍保存在数据库并在应用内计算相似度，适合当前题库和中小规模资料。大规模语料仍需根据内存和延迟预算迁移专用检索系统。向量接口失败时保留可用的关键词检索结果，聊天模型本身故障仍返回明确错误。

## 行为与运行
AI 默认关闭。启用后会把当前题目、已有回答、当前追问、最近最多 8 条对话及检索片段发送到配置服务。每账号仅允许一个请求，全站同时最多两个；后端聊天请求总截止时间默认 90 秒、向量请求默认 20 秒，均覆盖正文读取，超时会取消上游交换及正文订阅并释放槽位；浏览器 120 秒，代理 130 秒。服务器修改环境变量后需重启。

对话仅保留在当前题目页面，离开即清空。AI 结果保留 Markdown，沿用 HTML 清洗。模型被要求引用本次片段编号和标明资料不足；引用与内容仍需核对，不能保证模型完全遵从。

V3 迁移新增 ai_documents、ai_chunks，V4 为 documents 增加 imported 标记，升级前按现有部署说明备份数据库。新增知识库内容也纳入数据库备份；无需独立向量服务。通过当前应用修改内容会自动使索引失效；若直接执行 SQL 维护数据，需重启应用重新核对索引。

## 本轮边界修复

快捷提问不会清空尚未发送的输入草稿。来源题目在新标签页打开，当前页面对话保留；主动离开本题仍会清空对话。采用回答时校验路由及题目，防止迟到响应覆盖另一道题的编辑草稿。未启用状态可点击“重新检查”。

供应商响应须是 JSON 对象，聊天内容须为字符串；向量索引须为合法整数，元素须为有限数值，同一批次维度一致。格式错误返回 502；接口错误不会被当作可保存的回答或向量。

当前仍按单实例设计，会话、并发槽与索引失效状态保存在进程内。真实模型的事实正确性、引用正确性和检索相关性需要单独评估，格式检查不能替代内容核验。测试范围见 [测试指南](../docs/TESTING.md)。

## 资源预算与指标

服务器 `.env` 可设置下列预算，修改后重建后端：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| AI_REQUESTS_PER_HOUR | 30 | 每账号滚动一小时请求额度；聊天与向量构建共用 |
| AI_CHAT_TIMEOUT_MS / AI_EMBEDDING_TIMEOUT_MS | 90000 / 20000 | 上游完整交换的总截止时间 |
| AI_MAX_INPUT_CHARACTERS | 80000 | 完整聊天消息的字符总数，含系统说明、资料及历史；不是精确 token 计费估算 |
| AI_MAX_OUTPUT_TOKENS | 2048 | 发送给兼容供应商的 max_tokens 上限 |
| KNOWLEDGE_MAX_CHARACTERS | 5000000 | 上传资料累计字符预算 |
| KNOWLEDGE_MAX_CHUNKS | 10000 | 检索快照分片预算；上传前也检查新增分片 |
| KNOWLEDGE_MAX_VECTOR_BYTES | 134217728 | 快照保留向量的内存预算，保守计入编码及数组成本 |

超出向量内存预算的片段保留关键词检索能力；快照分片超过预算时返回明确错误，不静默截断全文。MySQL 分片采用流式读取。管理员指标包含 AI 接受/成功/错误/限流、总耗时、索引重建次数和耗时、语义降级及向量预算跳过数。

额度与指标仍在进程内，重启会重置；当前只支持单实例，不把这些计数当成持久账单或跨实例配额。真实模型事实与引用正确性需要另外评估。
