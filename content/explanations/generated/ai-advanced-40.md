## 参考回答

> 场景与约束：网银自动化沙盘:代码执行 Agent 直接跑在宿主机(可读文件系统、可出网)——注入(第 25 题)或模型失误即可造成越权。Agent 的执行环境按"假设会出错"设计:沙箱隔离+最小权限+出口管控。

1. 沙箱三要素:文件系统隔离(容器/临时目录,只挂载任务必需)、网络出口管控(白名单出口,默认拒绝——Agent 被诱导外传数据即被断路)、资源限额(CPU/内存/时长上限,防失控循环)。
2. 最小权限:工具清单按任务动态授予(本次任务只挂载需要的工具,第 37 题权限层),凭证按工具发放且短时效——Agent 全局凭证=全局事故半径;高危动作(资金/删除)一律人审。
3. 出口审计:沙箱内所有出网与工具调用留痕(目的地/载荷摘要)——事后可审计+异常外联实时告警;审计与权限同源(第 37 题权限层),不另建体系。

## 参考分析

### 机制:为什么默认假设会出错

Agent 的行为=模型输出,模型输出有幻觉与被注入的可能(概率不为零)——安全设计不能依赖"模型会做对"。沙箱的哲学=把"出错的代价"限制在沙箱内:错误代码跑在临时容器里(删了就没了)、错误外联被白名单拦(传不出去)、错误循环被限额杀(不烧穿资源)。类比生物实验室:实验(模型行为)假设会泄漏,负压房(沙箱)保环境。

### 反例:沙箱缺失的三种事故

事故一:代码执行直跑宿主——注入的代码读到了宿主上的配置文件(凭证泄露);修复=容器隔离+只挂载任务目录。事故二:出网不限——被诱导把数据 POST 到外部站点(数据外泄);修复=出口白名单+外联审计。事故三:全局凭证——Agent 持有完整 API key,注入后用同一凭证横向操作其他系统;修复=按工具短时效凭证+权限层强制(第 37 题)。

### 取舍:隔离强度与任务效率的平衡

强沙箱(独立容器每任务):安全但启动开销与工程复杂;轻沙箱(进程级+系统调用过滤):低开销但隔离弱;按任务风险分级——执行外部代码/处理不可信内容=强沙箱,内部固定流程=轻沙箱。分级与第 35 题量化矩阵同构:隔离强度跟风险走。

## 案例

### 验证:沙箱防线的推演核对

推演核对(教学示例):三注入场景(读文件/外联/超时循环)入沙箱 Agent——预期:文件读取被限定在挂载目录(宿主路径拒绝)、外联被白名单拦截且告警、循环被资源限额终止;审计留痕三类事件齐全。验证:每类事件的拦截断言与审计断言可程序化;对照无沙箱形态(三类全部成功)——沙箱的必要性有对照;方法与 OWASP LLM 的 Agent 安全线一致。

### 追问链:沙箱三刀

一刀:"沙箱里的模型调用呢?"——沙箱内对外调用走代理(统一出口),模型 API key 不落沙箱(代理持有)——沙箱被攻破也拿不到凭证。二刀:"人审的延迟怎么接受?"——高危动作异步+通知(审批流),Agent 挂起等待;紧急场景预先授权白名单(限定参数范围)。三刀:"沙箱逃逸的测试?"——红队集(第 43 题)专设逃逸用例(路径穿越/出网编码混淆),沙箱防线也要被红队验证,不是"有沙箱就安全"。

## 总结点

1. 假设会出错:沙箱隔离+最小权限+出口管控
2. 凭证按工具短时效,不全局发放
3. 审计与权限同源,红队验证防线
