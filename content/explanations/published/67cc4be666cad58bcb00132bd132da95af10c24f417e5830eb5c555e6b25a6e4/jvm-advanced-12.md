## 参考回答

<!-- explanation:deep -->

> 场景与约束：Java heap dump 显示对象总量很大，需要找出释放某个引用后可能回收的最大对象集合。讨论 shallow size、retained size 与业务所有权。

1. Dominator tree 用支配关系表示某对象独占控制的可达子图，retained size 估计释放它后可能一起不可达的内存。
2. retained size 是诊断线索，不是“删掉这个对象就一定能释放”的业务建议；要沿引用链找到真正的持有者和生命周期。
3. 应结合多次 dump、GC 后趋势、线程/缓存状态和代码审查，处理 dump 中的敏感数据与采集成本。

## 参考分析

### 支配与保留

若对象 A 支配一组对象，所有从 GC root 到这些对象的路径都经过 A；retained size 比 shallow size 更接近潜在释放收益，但工具算法和快照时点会影响解释。 需要结合目标 JDK、固定负载、采样窗口和重复运行验证，不能只凭一次快照或单次压力结果下结论。类比公司组织树：部门经理支配其下属的预算（保留大小），裁掉经理整组释放——dominator tree 就是按这条线看内存。

### 根引用优先

静态集合、ThreadLocal、线程、类加载器、队列和缓存通常比叶子对象更值得调查。删除叶子并不能改变根引用关系。 需要结合目标 JDK、固定负载、采样窗口和重复运行验证，不能只凭一次快照或单次压力结果下结论。

### 时间序列很重要

单个 dump 只能显示某一时刻。多个相同负载窗口的 dump 与 GC 后存活量结合，才能判断增长趋势和修复效果。 需要结合目标 JDK、固定负载、采样窗口和重复运行验证，不能只凭一次快照或单次压力结果下结论。

## 案例

### 树分析

在隔离环境制造有界缓存和无界缓存，分别导出 dump，比较 dominator、retained size 和根路径。预期无界缓存的持有者占比持续扩大。 需要结合目标 JDK、固定负载、采样窗口和重复运行验证，不能只凭一次快照或单次压力结果下结论。

### 安全验收

修复后验证 retained size、GC 后 live set 和业务缓存指标下降，并确认 dump 文件访问权限和删除策略。 需要结合目标 JDK、固定负载、采样窗口和重复运行验证，不能只凭一次快照或单次压力结果下结论。

## 总结点

1. 裁掉经理，整组预算释放
2. 先定义边界和不变式
3. 证据优先于直觉判断
4. 验证恢复与异常路径
