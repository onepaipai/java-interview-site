## 参考回答

<!-- explanation:deep -->

> 场景与约束：网银 AI 沙盘:大模型(LLM)=大规模预训练语言模型(GPT/Claude/GLM)——token=文本切分单位(不是词,是子词);token 是计费与上下文长度的计量单位(第 57 题 ai-production)。

1. 大模型(LLM):基于 Transformer 的大规模预训练语言模型——参数量(十亿到万亿)+训练数据(海量文本)+能力(生成/理解/推理/对话);LLM 不是数据库(不能查询事实),是语言模型(基于训练分布生成文本——第 31 题知识归 RAG)。
2. token:模型处理文本的最小单位——中文≈1-2 字/token,英文≈1 词/1-3 token;计费与上下文窗口都按 token 计(第 22 题预算);token 计数≠字符数(第 57 题 ai-production)。
3. 上下文窗口:模型一次能处理的最大 token 数(GPT-4 128K/Claude 200K)——窗口内所有内容(系统提示+检索片段+对话历史+用户问题)共享窗口;超出→截断或压缩(第 32 题压缩方案)。

## 参考分析

### 机制:LLM 的知识来自训练分布

LLM 的知识=训练数据的压缩表示(参数中的统计模式)——不是查询而是生成(基于上下文预测下一个 token);训练截止后的知识=不知道(幻觉风险)——RAG 解决(检索最新知识注入上下文,第 31 题职责分离)。

### 反例:LLM 理解偏差的两种事故

事故一:把 LLM 当搜索引擎——帮我查最新利率→用旧数据回答(过时);修复=RAG 注入最新数据。事故二:把 token 当字——中文与 token 不是 1:1;计费与窗口估算按 token 而不是字符数(第 22 题)。

### 取舍:模型选型的维度

能力(通用/代码/数学)+窗口大小(4K/32K/128K/200K)+成本(输入/输出单价)+延迟(首 token/生成速度)+合规(数据出境/私有化,第 45 题)——模型选型=多维矩阵(第 35 题量化矩阵同构),用业务评测集实测(第 1 题)。

## 案例

### 验证:LLM 概念的走查核对

验证:token 计数断言(中文/英文 token 数与字符数不同——tokenizer 实测);上下文窗口断言(超窗口→截断或报错);知识截止断言(训练后事件→不知道);幻觉断言(要求输出不存在的事实→可能编造)。验证:概念断言可程序化(调用 API 实测);Y1 成本模型的 token 计量可复用。

### 追问链:LLM 三刀

一刀:temperature=0 确定性(结构化输出)>0 随机性(创意)——温度低→稳定。二刀:大模型 vs 小模型=能力强+成本高 vs 能力弱+成本低——路由(第 22 题)按复杂度分配。三刀:私有化部署 vs API=数据不出域 vs 能力强+成本线性(第 45 题混合路由)。

## 总结点

1. LLM=生成模型,不是搜索引擎
2. token 计量≠字符数
3. 知识截止→RAG 补充最新知识
