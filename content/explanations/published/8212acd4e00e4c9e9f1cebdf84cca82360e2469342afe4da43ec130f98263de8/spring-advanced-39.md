## 参考回答

<!-- explanation:deep -->

> 场景与约束：网银平台组沙盘:团队争论"测试统一用 Testcontainers 还是 H2"——H2 快但方言与行为有差异,Testcontainers 真但慢。用两者的能力边界说明:不是二选一,是分层分工。

1. H2 的定位:业务逻辑单元与 Spring 上下文的快速验证(秒级启动、无外部依赖);失真点:方言(窗口函数/JSON 函数/锁行为)、版本特性、执行计划——MySQL 特有行为在 H2 上不存在。
2. Testcontainers 的定位:真数据库的真行为——迁移脚本(Flyway 在真 MySQL 上)、方言 SQL、锁与事务隔离、连接池行为;代价是启动分钟级与 Docker 依赖。
3. 分工矩阵:单元/上下文测试用 H2(本仓库大量测试即 H2);SQL 与集成测试用 Testcontainers(MySQL);本仓库的 MySQL 测试需要显式隔离配置(跳过不算验证)——正是分层的体现。

## 参考分析

### 第二步扩展① 机制:失真的来源与后果

- H2 模拟的是"一个数据库的通用行为",失真三类:方言(SQL 语法/函数兼容层掩盖真实报错)、并发与锁(H2 的锁粒度/MVCC 与 InnoDB 不同——行锁行为测试在 H2 上通过≠生产正确)、执行计划(索引选择的差异让"慢 SQL"在 H2 上永远测不出)。
- 后果形态:迁移脚本只在 CI 的 H2 上跑过,上线 MySQL 报语法错误。
- 锁竞态测试全绿,生产超卖(本机 D7 实验的超卖在 H2 上也可复现,但生产锁行为需真库)。

### 第二步扩展② 推演:分层测试的矩阵(附本仓库现状)

- 矩阵:第一层 H2 快速(业务逻辑/上下文装配/事务语义——本机三个真值示例全用 H2,秒级)。
- 第二层 Testcontainers-MySQL(SQL 兼容/迁移/锁行为)。
- 第三层预发真库(容量与执行计划)。
- 本仓库现状锚点:90 个后端测试中 13 个 MySQL 项需要显式隔离配置跳过——分层纪律已存在,缺的是第二层在 CI 的常态化(Docker 可用时必跑)。
- 验证:分层矩阵为工程推演。
- H2 层的快速验证本机实测(三个真值示例秒级完成)。

### 第二步扩展③ 取舍:CI 里的组合策略

- 策略:PR 门禁跑 H2 层(快,分钟内)。
- 每日/合并前跑 Testcontainers 层(Docker 可用性门控)。
- 预发跑真库冒烟。
- Testcontainers 的提速:容器复用(reuse)、单容器多测试类共享、按需拉起——分钟级可控。
- 失败语义:H2 层失败=逻辑错误。
- H2 过而 Testcontainers 挂=方言/行为失真,优先修测试真实度而不是绕过。
- 规则:凡断言"数据库行为"的测试禁止只跑 H2 就算验证(与"跳过不算验证"的仓库纪律一致)。

## 案例

### 第三步发散·验证与推演 验证:分层矩阵落地

- 验证:分层矩阵落地——PR 门禁跑 H2 层,合并前跑 Testcontainers 层(Docker 门控,不可用显式标注未验证)。
- 方言敏感的迁移与锁行为用例只放容器层,禁止 H2 单独算验证。

### 第三步发散·追问扩展 追问链:测试容器三刀

- **Q1：Flyway 迁移测试放哪层?**
  - 答：第二层(Testcontainers-MySQL):迁移的方言正确性只有真库能验(第 36 题的兼容期三步也在此验证)。
- **Q2：锁行为测试呢?**
  - 答：第二层:两连接竞争同一行的行为(InnoDB 行锁语义)在 H2 上不可靠;本机 D7 超卖实验可在真库上重做作为行为基准。
- **Q3：Testcontainers 挂了怎么区分环境问题?**
  - 答：容器启动失败与断言失败分开报告;Docker 不可用时显式 skip 并在报告标注"未验证"(与仓库纪律一致),禁止静默通过。

## 总结点

1. H2 验逻辑,容器验行为
2. 方言与锁,只有真库可信
3. 分层分工,跳过不算验证
