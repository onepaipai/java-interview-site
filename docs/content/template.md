## 参考回答

1. 直接回答原题，给出机制或具体做法，不先复述背景。
2. 写出关键前提：版本、资源、隔离级别或业务约束，按题目选择。
3. 说明方案何时成立、解决不了什么；有比较时给明确选择依据。
4. 只保留本题需要的工程动作，不堆“幂等、重试、监控”等通用名词。

## 参考分析

1. 用调用链、数据布局、状态或并发交错说明为什么成立。
2. 给出一个会让常见答案失效的边界或反例。
3. 用一个生活化类比或熟悉场景对照建立直觉，随后立即回到机制，不拿类比当结论。
4. 比较收益与代价，指出什么证据会改变方案选择。
5. 不改写参考回答凑条数；每点必须增加一条独立信息。

## 案例

1. 场景：明确业务输入、已有状态及约束；构造场景注明教学示例。
2. 实现：展示本题核心代码、SQL 或精确时序；手写题必须展示核心实现，不能只调用库替代。
3. 结果：给具体输出、状态变化、成功数量或判定条件；推导值与实测值分开。
4. 验证：指出在哪里注入失败、如何重放及失败后必须保持的约束。

## 总结点

1. 保留成立条件的核心短句。
2. 能区分易混概念的关键短句。
3. 一条口诀（对仗或押韵）后接机制短语，先有钩子、后有事实。
4. 能指导行动的实践短句。
