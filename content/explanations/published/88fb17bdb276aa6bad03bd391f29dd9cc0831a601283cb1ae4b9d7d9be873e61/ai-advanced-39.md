## 参考回答

<!-- explanation:deep -->

> 场景与约束：网银自动化沙盘:开户 Agent 已完成"创建账户",下一步"发送欢迎邮件"失败——部分成功的状态怎么办?多步编排的失败处理=检查点+补偿+续跑,不是从头再来。

1. 检查点:每步成功后把状态持久化(步骤序号+输出摘要+幂等键,第 38 题账本)——崩溃/失败后从检查点续跑,不重走已成功步骤(幂等键保证续跑安全)。
2. 补偿与回滚:步骤间有业务依赖(账户建了但初始化失败)时,失败路径要定义补偿(逆向动作或标记异常态)——补偿工具与正向工具同级别设计(幂等+可查询);不可补偿的(外部副作用已发生)转人工工单。
3. 失败分类决定路径:可重试(网络/超时——查单后重试)、业务失败(参数/前置条件——终止并输出失败原因)、不可恢复(基础设施故障——检查点挂起,告警人工);三类失败的处置在编排层显式定义,不靠模型临场决定。

## 参考分析

### 第二步扩展① 机制:部分成功是分布式事务问题

- 多工具编排=跨系统的 Saga(分布式 12 题同构):每步是本地事务,失败要补偿。
- Agent 的检查点=Saga 的状态机。
- 区别是 Agent 的步骤由模型动态决定——所以检查点与失败分类必须"框架级显式",把模型的自由度约束在"选择下一步"上,失败处理框架说了算。

### 第二步扩展② 反例:部分失败的两种事故

- 事故一:失败后从头重跑——已成功的"创建账户"再执行一遍(无幂等键时重复建户,有幂等键时安全但浪费)。
- 修复=检查点续跑。
- 事故二:补偿缺失——账户已建但流程终止,无人清理(僵尸账户)。
- 修复=失败路径显式定义补偿动作(或"保留+工单"的显式决策),不留中间态悬空。

### 第二步扩展③ 取舍:续跑、重跑与放弃的判据

- 可幂等续跑(检查点+幂等键):默认路径。
- 整体重跑:仅当步骤全幂等且成本低(纯读类)。
- 放弃+人工:不可补偿副作用+高价值操作(资金)——三类路径在编排配置里按工具声明,模型不参与失败策略决策。

## 案例

### 第三步发散·验证与推演 验证:编排失败的推演核对

- 推演核对(教学示例):五步编排在第 3 步注入失败——检查点续跑断言(步 1-2 不重执行,幂等键命中)。
- 补偿路径断言(失败步的前置成功步按声明补偿或保留)。
- 三类失败(可重试/业务/不可恢复)各自走向声明路径。
- 验证:检查点与补偿的断言可程序化。
- 对照"无检查点重跑"的重复执行形态——框架级失败处理的价值有对照。

### 第三步发散·追问扩展 追问链:编排三刀

- **Q1：检查点存哪?**
  - 答：持久化存储(与账本同库,第 38 题),格式含(任务 ID/步骤序号/工具/幂等键/输出摘要);摘要足够续跑判断,不全量存(上下文与存储双省)。
- **Q2：模型中途改主意怎么办?**
  - 答：已声明的编排计划+检查点是事实,模型改主意走"显式取消+补偿"流程,不是悄悄绕过。
- **Q3：多 Agent 的部分失败?**
  - 答：子 Agent 失败上抛给编排 Agent 处理,子 Agent 内部先按本框架处理;跨 Agent 的补偿协议要显式定义(消息+幂等键)。

## 总结点

1. 检查点续跑,不从头重跑
2. 补偿路径与正向工具同级设计
3. 失败三类分类,框架定路径
