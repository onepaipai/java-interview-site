# 知序：界面与核心流程审查
日期：2026-10-13。范围：题目与回答 CRUD、知识模块、账号管理。不修改产品代码、不增加自测、统计、收藏、AI 等功能。

## 审查结论
当前核心功能可用，但页面仍有模板感。主要原因是信息密度、视觉规则和操作反馈不统一；多次叠加样式形成了页面之间的差异。
建议方向：清晰、克制、内容优先的知识工作台。用模块导航组织内容，阅读区突出问题和答案，管理功能使用一致的表单和反馈。

## 已核实的发现
1. 实测桌面和手机：模块与题目切换后 URL 没有变化，刷新后回到知识目录，不能直接分享具体题目。
2. 手机题目编辑区拥有独立完整工具栏和较高空白区域，回答区被推到首屏下方；底部保存栏在视口内占据回答编辑器上方空间。
3. 模块按钮桌面 11px、手机 10px。按当前 CSS 文字 #8d96aa、背景 #fdfdff 计算，对比度约 2.92:1，低于 WCAG 普通文本 4.5:1。
4. 账号修改名称和重置密码使用 window.prompt；删除账号使用 window.confirm。重置密码输入框没有密码遮罩。
5. 页面请求没有一致的局部加载状态，正在请求时可能暂时显示旧内容或空白。
6. 代码显示：模块 question_count 只统计未删除题目，模块删除接口检查包括已删除题目的全部记录。因此可能显示空模块却无法删除。
7. 模块图标/色调按列表位置分配，搜索后同一模块可能换图标或色调。
8. 首页搜索只搜索模块名；问题与回答搜索要先进入模块才能使用。
9. 页面样式分布在 style.css、redesign.css、module-manager.css，出现重复选择器及后置覆盖。

## 修改顺序和验收
第一轮：核心流程
- 给模块和题目独立地址；刷新、浏览器前进后退、分享链接保持当前位置，返回列表保留筛选、分页和滚动位置。
- 账号操作统一站内弹窗。密码默认遮罩，错误贴近对应字段，提交期间阻止重复操作。
- 统一空模块统计与删除规则，保留历史数据，不通过悄悄永久删除题目解决问题。
- 请求有局部加载、失败重试；避免旧请求覆盖用户刚切换后的页面。

第二轮：内容工作台
- 电脑：可折叠模块导航 + 内容区；首页仍按模块展示，不平铺所有题目。手机：模块导航进入抽屉，保留明确返回路径。
- 模块内题目采用紧凑列表，回答阅读区约 720–800px；编辑操作收在右上方，删除操作进入更多菜单。
- 长答案根据 Markdown 标题生成目录，短答案不显示目录。
- 保留题目 Markdown，但默认提供紧凑编辑区；复杂题目再展开。回答保留分屏与图片功能。手机工具栏收敛常用操作，其他放更多菜单。
- 模块名称、数量、进入动作优先，卡片缩小无效留白。固定模块图标身份。
- 全局搜索题目与回答，以模块分组返回结果，不改变默认模块目录。

第三轮：视觉一致性
- 抽取统一色彩、字号、间距、圆角、边框与按钮规范。
- 主色只用于选中和主要操作；减少无意义的彩色图标、徽标和标语。
- 正文建议 16px，常用操作 13–14px；细小辅助信息也应清楚可读。依 WCAG 核验对比度，并实测手机触控。
- 成功反馈使用不会推动内容的短暂提示，失败信息留在操作位置。
- 优先完善明亮主题、中文排版和键盘/手机体验。暂不增加深色模式、复杂动画或新的业务功能。
