> 场景与约束：网银配置沙盘:开发用内存 DB 测试用 H2 生产用 MySQL——行为差异方言事务精度导致测试通过生产失败——配置一致性同一制品加环境外置加差异最小化。

1. 一致性的三个层面制品一致同一 jar 多环境部署,依赖一致开发用 MySQL 驱动加 H2 兼容层 vs 生产用 MySQL 方言差异,行为一致 H2 与 MySQL 的 SQL 方言事务隔离锁行为差异。
2. 差异最小化 H2 尽量接近 MySQL MySQL 兼容模式——但 H2 无法完全模拟 MySQL 关键路径用 Testcontainers 真库验证——配置的分级开发容忍差异测试真库验证。
3. 配置的外置 application profile yml 环境差异加 common yml 共性——环境差异只体现在配置连接串开关代码行为一致——配置差异的显式化。

## 参考分析

### 第二步扩展① 机制:配置一致性的三层保障

- 制品一致 同一 jar 多环境部署。
- 依赖一致 开发用 MySQL 驱动加 H2 兼容层 vs 生产用 MySQL 方言差异。
- 行为一致 H2 与 MySQL 的 SQL 方言事务隔离锁行为差异。
- 差异最小化 H2 尽量接近 MySQL 加关键路径 Testcontainers 真库验证。
- 配置外置 环境差异只体现在配置。

### 第二步扩展② 反例:配置差异的三种事故

- 事故一 制品不一致 测试包含 mock 数据源发到生产。
- 事故二 依赖差异 H2 与 MySQL 的行为差异导致测试通过生产失败。
- 事故三 配置漂移 生产配置被误改未发现。
- 修复 同一制品加配置外置加差异审计。

### 第二步扩展③ 取舍:差异的容忍度

- 开发容忍差异 H2 替代 MySQL 功能测试足够。
- 测试不容忍差异 Testcontainers 真库。
- 生产零差异 同一制品加配置外置。
- 差异容忍度按环境递减开发大于测试大于生产。

## 案例

### 第三步发散·验证与推演 验证:配置一致性的断言组

- 验证:制品断言(各环境部署同一哈希制品)。
- 差异审计断言(配置 diff 环境间的差异清单)。
- 行为断言(H2 与 MySQL 的行为差异清单已知差异文档化)——三组固化配置一致性。
- 差异清单随发布物归档,新增差异必须过评审,防配置漂移静默累积。

### 第三步发散·发散要点 追问链:配置一致三刀

- **追问①**：配置的版本管理配置文件进版本控制代码同仓库加敏感配置外置 KMS 配置的版本可追溯
- **追问②**：环境隔离开发测试生产的环境隔离数据网络权限环境间的配置差异最小化
- **追问③**：配置的审计配置变更的审计谁何时改了什么配置变更走审批生产配置

## 总结点

1. 同一制品环境外置
2. 差异最小化关键路径真库验证
3. 配置差异显式化
