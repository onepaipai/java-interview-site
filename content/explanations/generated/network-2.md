## 参考回答

1. 客户端、JVM、本地解析器和递归服务器可能分别缓存结果，实际生效时间不只由权威 TTL 决定。
2. 迁移前应验证完整解析链。

## 参考分析

1. DNS TTL 只约束相应缓存，应用可能继续复用早先建立的连接。
2. 切流要同时看解析结果、连接池远端地址和旧节点摘流。

## 案例

1. 场景（教学示例）：域名切到 B，某个 Java 客户端仍把请求发往 A。

2. 处理：记录解析时间与实际远端地址，按预算更新连接生命周期；A 保留迁移兼容窗口。

3. 验证：能区分旧 DNS 与旧连接，不靠无限缩短 TTL 掩盖长连接残留。

## 总结点

1. DNS 与连接分开查。
2. 切流保留兼容窗口。
