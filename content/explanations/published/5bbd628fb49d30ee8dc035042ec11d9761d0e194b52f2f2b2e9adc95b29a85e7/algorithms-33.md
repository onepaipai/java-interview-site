## 参考回答

<!-- explanation:deep -->

> 场景与约束：网银任务编排沙盘:任务间有依赖(对账依赖清分,清分依赖日切)——依赖成环=编排死锁;Kahn 算法(入度清零)既给执行顺序又给环检测:队列空时仍有剩余节点=有环。

1. Kahn 算法:①统计每节点入度;②入度 0 的进队列(无依赖,立即可执行);③出队一个,把它的后继入度各-1,减到 0 入队;④输出顺序即合法拓扑序——终止时输出数<节点数⇔剩余节点入度都>0⇔环(环内互相依赖,入度永远清不到 0)。
2. 环的定位(进阶):剩余节点即「环上或环下游」——要精确找环:在剩余子图上 DFS 三色标记(第 34 题)或从任一剩余节点沿边走直到重复(环提取);工程上通常输出「环上任务清单」供人工解除依赖,不必提取精确路径。
3. 与 DFS 拓扑的对比:DFS 后序逆序也是拓扑序(有向无环时)——但 DFS 天然不产出环检测的「顺序证据」(三色能判环);Kahn 一箭双雕(顺序+检测)且天然支持动态调度(入度 0 即可并行发射——任务编排器的并行度来源);两者结果序都合法但不唯一(并列无依赖的任务顺序任意)。

## 参考分析

### 机制:入度清零为什么等价于无环

DAG 必有入度 0 的节点(否则从任意点逆依赖回溯必无限——与有限矛盾)——删掉它,剩余图仍是 DAG,归纳可得全序;若有环:环内每节点入度≥1(环内前驱),任何时刻都清不到 0,队列提前枯竭——「队列空了还有剩」就是环的存在性证明;这个构造性证明同时给出了算法,是「证明即算法」的典型。

### 反例:拓扑三刀

事故一:入度减完忘查 0 直接入队(把负数/非零也塞)——顺序错乱;事故二:环检测只看「是否全部输出」不看输出数量——漏报(要计数对比);事故三:依赖关系存储在表里但查询用循环逐个找——邻接表构建 O(V+E) 一次性建好,别在主循环里反复扫;事故四:把「拓扑序不唯一」当 bug——并列任务的任意顺序都合法,测试断言要用「约束满足」而非「序列相等」。

### 取舍:Kahn vs DFS vs 环检测专用

要执行顺序+并行发射:Kahn(队列=就绪集合);只要判环:三色 DFS 更直接;构建系统(增量重算):Kahn+脏标记(Maven/Gradle 的任务图);依赖图巨大(万级任务):邻接表用数组/CSC 压缩;与并查集(第 32 题)的分工:无向连通用集,有向依赖用度。

## 案例

### 验证:拓扑断言组(本机可复跑)

验证:合法性断言(随机 DAG,输出序满足每条依赖边 u 先于 v——全边核对);环断言(A→B→C→A 注入,输出数<节点数且剩余=环成员);环下游断言(环外依赖环的节点也在剩余集——被传染);并行度断言(入度 0 集合=可同时发射的初始任务);金标对照(DFS 后序逆序与 Kahn 序都满足约束——不唯一性验证)。预期:约束满足断言+环定位双闭环。

### 追问链:拓扑三刀

一刀:任务编排器实现——Kahn 队列=线程池任务源(第 49 题并发调度衔接:发射并发受限则队列+信号量);二刀:构建缓存——任务输出指纹不变跳过(Maven增量),拓扑序决定指纹传播方向;三刀:数据迁移依赖(Flyway 版本链,第 44 题 db-basics)与包管理依赖解析(npm/yarn 的扁平化)都是拓扑的应用,Kahn 的「环报错」就是版本冲突的报错原型。

## 总结点

1. 入度清零=可执行,队列枯竭=有环
2. 删点归纳:DAG 必有零入度
3. Kahn 顺序+检测一箭双雕
