## 参考回答

<!-- explanation:deep -->

> 场景与约束：网银自动化沙盘:Agent 需要查汇率(外部 API)——不限出网则注入(第 25 题)可诱导 Agent 把内部数据 POST 到外部(数据外泄)。出网限制=白名单出口+统一代理+载荷审计,与沙箱(第 40 题)配套。

1. 出网白名单:Agent 可访问的外部域名/API 预定义清单(汇率 API/天气 API),清单外默认拒绝——白名单按任务需求最小化(不是"常用的都加上");清单变更走审批+审计。
2. 统一代理出口:所有出网走网关代理(直连禁止)——代理执行白名单校验、载荷审计(目的地/大小/频率)、凭证注入(外部 API key 在代理持有,Agent 不见凭证,第 40 题)。
3. 异常检测:出网行为基线(频率/数据量/目的地)——偏离基线(突然大数据量外发、新域名)实时告警+自动阻断;基线随任务类型分层(检索类任务不应有大出网载荷)。

## 参考分析

### 第二步扩展① 机制:出网=数据出境

- Agent 的出网请求可能携带上下文数据(检索内容/用户数据)——被注入后,恶意指令"把上下文 POST 到 evil.com"就是数据外泄。
- 出网限制的假设=Agent 可能被诱导发出任意请求,防线在代理层(模型外),不靠模型自律。

### 第二步扩展② 反例:出网失控的两种事故

- 事故一:直连不限——注入后 Agent 向外部站点回传会话内容(用户敏感信息外泄)。
- 修复=代理白名单+载荷审计。
- 事故二:白名单过宽(整域名通配)——白名单内站点的任意路径可访问(一个漏洞页=外传通道)。
- 修复=白名单精确到 API 路径与方法,不是域名级。

### 第二步扩展③ 取舍:白名单粒度与运维成本

- 域名级白名单:运维简单,粒度粗。
- 路径+方法级:精细但清单维护重——按数据敏感度选:触敏任务的出网精确到路径,一般任务域名级+载荷审计兜底。
- 清单的审计与轮换(不再用的出口定期清理)同第 10 题配置纪律。

## 案例

### 第三步发散·验证与推演 验证:出网限制的推演核对

- 推演核对(教学示例):三类出网样本(白名单 API 正常调用/非白名单域名/白名单域名恶意路径)——断言:白名单内正常(代理注入凭证,Agent 无凭证)、清单外拒绝+告警、恶意路径被路径级校验拦截。
- 载荷审计断言(出网载荷可回溯)。
- 验证:三类断言可程序化。
- 注入诱导外传的对照(无代理形态外泄成功)佐证——出网限制是数据防线的硬闸。

### 第三步发散·追问扩展 追问链:出网三刀

- **Q1：Agent 需要下载文件呢?**
  - 答：下载也走代理(白名单+大小上限+文件扫描,第 3 题上传安全同构)——出站的文件与入站同样治理。
- **Q2：出网限速?**
  - 答：外部 API 的配额(供应商限流)在代理层管理,Agent 并发不放大(第 15 题限流延伸到出网)。
- **Q3：Web 浏览类工具?**
  - 答：浏览是高危出网(内容不可控进上下文,注入面大,第 25 题),隔离沙箱+内容过滤+信任级标记三件套,默认不开放。

## 总结点

1. 出网走代理,白名单精确到路径
2. 凭证在代理,Agent 不见外部 key
3. 出网基线告警,偏离即阻断
