# UI、交互与答案深度审查 · 2026-10-19

本轮只审查，未修改业务代码、题目或答案。结论：目前最需要处理的是答案与原题的对应关系、搜索相关性及摘要提取；继续调整卡片颜色的收益较小。

## 范围与判断依据

- 全量扫描当前发布清单的 1,215 道解析，统计正文来源和完全相同的案例；按题型定向抽读 65 道，覆盖全部 21 个知识模块及原始题。抽样不是随机抽样，不能用它推算全库错误率。
- 通过真实站点验证目录、模块列表、全局搜索、阅读页、编辑预览、知识库来源预览和返回流程，检查 1440×1000、390×844、320×740 三种视口。
- 当前业务库为 1,216 道有效题、326 道归档题；仅登录、读取和切换视图，未保存编辑、上传文档、删除内容或调用模型。
- `vue-tsc --noEmit`、`validate-content.mjs`、`validate-explanations.mjs`、`tests/knowledge-core.mjs` 通过。结构和哈希验证不能证明技术内容正确；本轮未重跑全量后端测试，也未验收真实 AI 模型。
- 截图、抽样清单和统计保存在 `frontend/test-results/deep-review-20261019/`，不随发布源码包交付。

## P1：优先处理

### 1. 分析、案例和总结串到其他题目，影响学习结论

**证据：** 当前 1,215 道解析中，203 道使用题目级正文、2 道固定样例、1,010 道使用主题正文；974 道与其他题使用完全相同的案例，分成 189 组。复用不自动等于错误，但下列抽查已确认偏题：

| 题目 | 实际内容 | 问题 |
| --- | --- | --- |
| #693：HashMap 为什么不适合并发读写 | 分析讲树化和遍历成本；案例是单线程不可变键；总结讲容量 | 没展示并发交错，也没总结并发安全边界 |
| Java 并发实战第 35 题：按键串行、不同键并行执行器 | 分析和总结变成 StampedLock 乐观读；案例是跨段转账锁 | 缺少任务队列、同键调度和通道回收的机制 |
| MySQL 基础第 35 题：NULL 比较与唯一约束 | 分析讲 MyBatis 参数绑定和 DELETE/TRUNCATE/DROP | 没解释三值逻辑及目标 MySQL 的唯一约束行为 |
| #846：BeanFactory 与 ApplicationContext | 案例和总结主要讲构造器注入、Qualifier | 没验证两种容器职责差异 |

**位置：** [collections-2.md](../../content/explanations/generated/collections-2.md:16)、[concurrency-advanced-35.md](../../content/explanations/generated/concurrency-advanced-35.md:16)、[database-basics-35.md](../../content/explanations/generated/database-basics-35.md:16)。这些审阅副本与清单指向的已发布正文一致，且 #693 在业务库和页面上复现。

**建议：** 优先重写已发现串题的正文；共享主题仅作为背景材料，不能直接填充每题的案例和总结。每题要求回答、案例验证目标、总结三者一致，分析没有独立信息就省略。

**验收：** 给案例遮住题目标题后，仍能判断它验证的是哪一个问题；总结能准确复述原题结论。

### 2. SynchronousQueue 的教学处理包含错误操作暗示

**证据：** #716／集合第 25 题问零容量交接，案例却写“设定有界容量”，未说明这是更换队列设计，容易被理解为给 SynchronousQueue 配置存储容量。该类没有内部容量；构造器只接受可选公平性参数，`offer` 的等待对象是接收线程。参见 [Java 17 官方 API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/concurrent/SynchronousQueue.html)。

**位置：** [collections-25.md](../../content/explanations/generated/collections-25.md:24)。

**建议：** 用两个线程展示交接；分别验证无消费者时 `offer` 返回 false、等待接收者出现后成功，以及超时和中断。如果讨论换成有界缓冲队列，应明确指出这是另一种设计。

### 3. 精准搜索被通用参考链接污染，原题排不到前面

**复现：** 全局搜索输入 `Raft`，得到 240 条结果；前几条为 TCP、HTTPS、HTTP 状态码、Cookie、设计模式和 Git。首批 30 条没有“Raft 的多数派为什么需要与任期和日志规则配合？”这道标题直接命中的题。

**根因：** SQL 在完整 `answer` Markdown 上做 LIKE，参考资料里的 Raft 链接被当成知识正文；结果仅按分类、题目顺序排列，没有标题命中优先级。

**位置：** [QuestionService.java](../../backend/src/main/java/dev/interview/QuestionService.java:43)、[GlobalSearch.vue](../../frontend/src/GlobalSearch.vue:8)。搜索列表和题目定位接口应同步采用相同排序规则，避免修正排序后上下题顺序错位。

**建议：** 搜索内容使用去参考资料、去 HTML 的有效正文；标题精确/前缀/词命中优先，再排正文；摘要围绕实际命中位置生成。

**验收：** 搜索 Raft，标题直接命中的题处于首批靠前位置；只在通用参考链接出现该词的题不挤占结果。

## P2：内容深度与阅读体验

### 4. 高级题回答停留在提醒层，缺少能支撑结论的机制

**证据：** #1446 的 Raft 题写“还依赖选举和日志匹配规则”，分析又写“须配合任期、日志与成员规则”，没有展开关键规则。#1053 的内存屏障题只提醒“先用规范说明结果”，没展示具体的发布—读取关系，案例又转成 CAS 更新版本。

**建议：** 保持干练，但每点给出实际规则。例如 Raft 可以用“候选日志新旧判断”“本任期日志的多数提交”“旧任期日志通过后续提交间接确认”解释一个五节点反例，而非继续添加概括性提醒。依据为 [Raft 原论文 §5.4.1–5.4.2](https://raft.github.io/raft.pdf)。

**位置：** [distributed-5.md](../../content/explanations/generated/distributed-5.md:14)、[concurrency-advanced-12.md](../../content/explanations/generated/concurrency-advanced-12.md:13)。

这里的判断是“不足以达到题目要求的解释深度”，不把所有简短答案判成事实错误；LRU、余弦/欧氏距离、部分事务样例已有针对性机制和验证，质量明显更好。

### 5. 回答与分析仍存在换词复述

**证据：** Java 语言第 3 题的回答先写浮点不能精确表示多数十进制小数，分析再次写同一结论；网络第 12 题的两段都在讲 HTTP 状态类别与业务错误码。当前只有 7 道解析省略分析，这不证明其他题都重复，但说明去重只在少量样例中落地。

**建议：** 同一句结论保留一次；分析只能增加机制、反例或取舍，不能为凑固定段落改写原句。

**位置：** [java-language-3.md](../../content/explanations/generated/java-language-3.md:18)、[network-12.md](../../content/explanations/generated/network-12.md:17)。

### 6. 全局搜索摘要直接暴露 HTML 标记

**复现：** 搜索 HashMap 或 Raft，结果摘要出现 `<details class="explanation-references"`、`<summary…` 等源码。文本通过 Vue 插值展示，不是本次发现的脚本执行漏洞，但严重影响阅读。

**根因：** `plain()` 只去掉部分 Markdown 字符，保留 HTML；知识库已有更完整的摘要清理，但全局搜索没有复用。

**位置：** [GlobalSearch.vue](../../frontend/src/GlobalSearch.vue:7)。

**建议：** 共用安全的摘要提取器，先排除参考块，再提取纯文本及命中上下文；不要用更多零散正则补丁维护不同版本。

### 7. 模块列表摘要相同，不能帮助选题

**复现：** Java 集合前四道题摘要均以“适用范围与模块参考资料 Java 示例以 17 为基准…”开头，90 字额度基本耗在相同资料说明上。

**根因：** 对回答前 600 字直接转纯文本，再截取 90 字；参考资料块位于所有发布答案的开头。

**位置：** [useWorkbench.ts](../../frontend/src/useWorkbench.ts:523)。

**建议：** 有搜索词时展示实际命中上下文，否则提取参考回答首个要点；同一列表的摘要应能体现题目差别。

### 8. “完整资料预览”静默丢失流程图

**复现：** 知识来源预览 #1142“事务代理为什么会在同类自调用时失效？”，正文说“下图只展示该失败路径”，随后没有图，也没有占位或查看图片入口。

**根因：** 预览统一使用 `media:false`，本地受控流程图也一起删除。过滤外部媒体有其作用，但静默删除破坏了完整阅读语义。

**位置：** [KnowledgeManager.vue](../../frontend/src/KnowledgeManager.vue:51)、[markdown.ts](../../frontend/src/markdown.ts:9)。

**建议：** 受控同源 `/explanations/` 图片可以单独允许；其他媒体至少保留“此处包含图片，查看原文”的占位，不能留下“见下图”却不给出口。

### 9. 编辑器预览与正式题解不是同一种排版

**复现：** #693 的回答预览存在 4 个普通 h2，但没有 `.explanation-content`；正式阅读则有段落序号、连续题解分段和案例图注。管理员看到的“阅读效果”与保存后的页面不一致。

**位置：** [MarkdownEditor.vue](../../frontend/src/MarkdownEditor.vue:12)、[useWorkbench.ts](../../frontend/src/useWorkbench.ts:57)。

**建议：** 回答预览复用正式阅读的格式化流程；题目 Markdown 仍按题目规则渲染，避免混用。

### 10. 知识库返回操作丢失工作位置

**复现：** 知识来源筛选“事务代理为什么会在同类自调用时失效”，切到题库，再用浏览器后退返回。页面回到空白的“检索资料”，原标签、关键词、类型和分页丢失。

**根因：** 标签与筛选状态都只放在组件 ref，地址始终是 `#/knowledge`。

**位置：** [KnowledgeManager.vue](../../frontend/src/KnowledgeManager.vue:24)。

**建议：** 将当前标签、已提交搜索词、来源筛选和页码写入路由；后退恢复视图，刷新后也能继续。不要持久化预览正文或服务密钥。

### 11. 手机阅读首屏重复信息多，长题换题成本高

**证据：** 390px 宽的 #693 页面在主导航、模块切换条、面包屑、题目卡、目录和参考资料入口后，参考回答约从页面 y=534px 开始。320px 宽的 LRU 题，换题导航约位于 y=2786px，目录又只在正文开头；没有阅读中途可用的换题入口。

**位置：** [App.vue](../../frontend/src/App.vue:147)、[QuestionDetail.vue](../../frontend/src/QuestionDetail.vue:86)、[reader.css](../../frontend/src/reader.css:77)。

**建议：** 手机合并重复的模块和面包屑信息；提供紧凑的目录/上一题/下一题阅读工具条，处理安全区和遮挡，保留足够正文空间。无需把所有操作都做成悬浮按钮。

这是使用成本问题，本轮三种视口未在所查页面发现正文横向溢出。

### 12. 辅助小字偏淡，手机搜索按钮缺少可访问名称

**证据：** AI 助手说明为 11px、`#8b95a7`，白底对比度约 3.02:1；目录页数为 10px、约 3.02:1。常规文字的 WCAG AA 最低参考为 4.5:1，参见 [W3C 说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。手机搜索按钮仅余图标，隐藏其 span/kbd 后可访问树中显示为无名称按钮。

**位置：** [reader.css](../../frontend/src/reader.css:48)、[reader.css](../../frontend/src/reader.css:71)、[App.vue](../../frontend/src/App.vue:122)。

**建议：** 非装饰文字统一可读字号和对比度；搜索按钮增加稳定的 `aria-label`。同时验证键盘、读屏、缩放及焦点样式。本轮不构成完整 WCAG 合规认证。

## 修复顺序

1. 先修确认偏题和错误操作暗示的答案；同批修正搜索正文及标题排序。
2. 统一搜索和列表摘要、正式阅读和编辑预览，补上图示缺失提示。
3. 优化手机阅读工具条、字号和无障碍名称，恢复知识库浏览状态。
4. 内容按题逐条验收：直接结论、必要机制、一个对应案例、一个关键失败路径、两三条能记住的总结。不得再把格式覆盖率当作内容质量完成率。

复用案例的 974 道题应列为核对范围，不能直接标成 974 道错误；也不建议再次一次性批量套模板发布。
