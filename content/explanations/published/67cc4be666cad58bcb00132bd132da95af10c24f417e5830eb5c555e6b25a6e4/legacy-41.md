## 参考回答

1. #{} 通常生成 PreparedStatement 参数占位并通过类型处理器绑定值；${} 把文本直接替换进 SQL，不能把不可信输入原样拼进去。
2. 参数占位适合值，不能替代列名、表名或排序关键字；动态标识符应由服务端有限白名单映射，不让用户任意指定 SQL 片段。

## 参考分析

1. 参数绑定保护值边界，不代表整条 SQL 免疫注入；混用字符串拼接、动态排序或错误权限仍会产生风险。
2. LIKE 可在 Java 侧构造带通配符的值再绑定；业务需要字面匹配时还需处理通配符语义，不能只关注 SQL 语法。

## 案例

1. 教学场景：查询接口用 ${keyword} 拼条件，并把客户端 sort 原样当作列名。

2. 查询值改为 #{} 绑定；sort 仅接受业务枚举并映射到固定列名及方向，未知字段直接拒绝。

3. 验证带引号的查询值只作为数据，非法排序被拒绝；同一用户仍只能查询授权数据，参数化不代替权限校验。

## 总结点

1. 值用绑定，标识符用白名单。
2. 文本替换不能接收任意输入。
