## 参考回答

<!-- explanation:deep -->

> 场景与约束：网银对账链沙盘:两条链表在某节点后共享同一条尾(交点后完全重合)——长度差消解法 O(1) 空间;核心事实:交点后长度相同,差只在交点前。

1. 核心事实:两链表一旦相交,从交点到尾完全重合(Y 形,不是 X 形——单链表 next 唯一,交点后不可能分叉)——所以「长度差」全部来自交点之前的部分。
2. 双指针交替法(最优,无长度差计算):pA 从 headA、pB 从 headB 同步走,各自到尾后跳到另一条链的头继续——若相交,两指针在交点相遇(走过的总长相同 a+c+b == b+c+a);若不相交,两指针同时到达 null(各走 a+b+c)——交替抵消长度差,代码最短。
3. 长度差消解法(直观版):先各算长度,长链先走差值 d 步,然后同步走,首对相等节点=交点(用引用同一性比较,不是值);不相交两指针同时 null——O(a+b) 时间 O(1) 空间;哈希法(存一条链,查另一条)O(min(a,b)) 空间换一次遍历。

## 参考分析

### 第二步扩展① 机制:交替法为什么必然相遇在交点

- 指针 pA 的路径 headA→…→null→headB→…,pB 对称——两者总路径长度相同(a+c+b 与 b+c+a)。
- 在共同路径段(交点后)它们「步调差」被前面的交换彻底消除:各自走过自己独有段+对方独有段后同时进入共享段同一位置——这个「交换抵消」是双指针技巧里最优雅的对称性论证。
- 不相交时交换同样对称,双 null 同时发生。

### 第二步扩展② 反例:相交检测的三种事故

- 事故一:用值相等判交点——两个不同节点 value 相同被误判相交(必须用 == 引用同一性)。
- 事故二:假设 X 形交叉——单链表交点后必然重合,X 形只存在于二叉树/有向图。
- 事故三:没先判环——带环链表的「相交」可能是环内交点,双指针交替会死循环(先各自 Floyd 判环,分「都无环/都有环共享环」讨论)。

### 第二步扩展③ 取舍:三种方法的选择

- 双指针交替:一次遍历+O(1) 空间,代码最短,面试首选。
- 长度差:两次遍历但逻辑直白(先证明「交点后重合」再消差)。
- 哈希:O(n) 空间但只遍历一条(另一条边走边查)——链表极长且只做一次时哈希最快。
- 面试追问「为什么 Y 形」是本题的深度锚点。

## 案例

### 第三步发散·验证与推演 验证:相交断言组(本机可复跑)

- 验证:相交断言(共享尾 7→8,A=1→2→7→8 B=3→4→5→7→8,交点==节点 7 的引用——交替法与长度差法对照)。
- 不相交断言(两条独立链,双双到 null)。
- 同长度相交断言(等长无差值,消除逻辑退化为同步)。
- 重合断言(一条是另一条的前缀——交点即短链头)。
- 值陷阱断言(两个 value 相同的不同节点——引用比较不误判)。
- 预期:五组全过,引用同一性是判据核心。

### 第三步发散·发散要点 追问链:相交三刀

- **追问①·带环链表相交怎么判——两环入口相同**：相交(交点可能在环前);入口不同=沿环走一圈找对方入口;先 Floyd 后讨论(第 12 题接力)
- **追问②**：为什么不用「值+去重」——业务链表 value 天然重复(金额/账户),引用语义才是身份
- **追问③**：工程迁移——Git 分叉合并基(共同祖先)、DOM 树最近公共容器(第 39 题 LCA 同思想,把 next 变 parent)

## 总结点

1. Y 形:交点后必然重合
2. 交替走,总长相等必相遇
3. 引用同一性,不是值相等
