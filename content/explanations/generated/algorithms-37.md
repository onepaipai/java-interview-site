## 参考回答

> 场景与约束：网银组织架构沙盘:按层级渲染部门树——层序遍历(BFS)天然逐层,但要把「层」切出来:每层计数法或哨兵法,别把整棵树一次性输出成平铺。

1. 每层计数法(推荐):队列放根;循环条件队列非空——先记 levelSize=queue.size()(本层节点数),内循环恰好弹 levelSize 次(弹出处理+子入队),内循环结束=本层完成;外层把本层结果打包——这是标准的「分层 BFS」模板。
2. 哨兵法(备选):每层末尾塞 null 哨兵——弹到 null 表示层结束(输出本层+再塞哨兵);缺点:节点值可能为 null 的树冲突,且队列里混 null 要小心;计数法无此问题——两层循环+size 快照,语义清晰。
3. 变体全部在分层上生长:锯齿形(奇偶层反向——奇层正常弹,偶层用 addFirst 或反转列表)/自底向上(结果 addFirst 整层)/右视图(每层最后一个)/最大宽度(记录每层首尾下标算宽度——完全树用编号,一般树用下标间距)——「分层」是所有树 BFS 题的共同骨架。

## 参考分析

### 第二步扩展① 机制:size 快照为什么恰好切层

- 入队发生在「处理本层节点时」——内循环开始前队列里恰好全是本层节点(上一层已弹空,子节点刚入),size 快照=本层节点数。
- 内循环弹 levelSize 次,弹的全是本层、入的全是下层。
- 快照的时机(内循环前)是唯一关键——放在循环内(每弹一次重新取 size)会把下层节点算进来,层就糊了。
- 这个「快照-处理-换层」结构与迷宫多源 BFS 的波纹扩散同构。

### 第二步扩展② 反例:层序的三种事故

- 事故一:size 取在循环内——层边界漂移,层结果混入下一层。
- 事故二:null 哨兵与 null 值冲突——树允许 null 值时哨兵法崩。
- 事故三:右视图误用「最后入队的孩子」——孩子入队顺序=左先右后,最后入队确实是右——但只对「每层恰好取一个」成立,混用「计数法打包后再取尾」更稳。
- 事故四:大树队列内存——宽树(万级同层)队列峰值 O(宽度),DFS 更省(树深相关),按树形态选。

### 第二步扩展③ 取舍:BFS vs DFS vs 编号法

- 逐层结构化输出:BFS+分层模板。
- 深度优先类(路径/祖先):DFS。
- 完全二叉树下标性质(第 i 层起止 2^i/2^(i+1)-1):直接算不用遍历——但一般树不行。
- 宽树省内存:DFS(栈深=树深,通常 log 级)vs BFS(队列宽=最大层宽)——形态决定选择(第 34 题图 BFS/DFS 语义差异同理:树无环,两个都安全)。

## 案例

### 第三步发散·验证与推演 验证:分层断言组(本机可复跑)

- 验证:分层断言(三层树输出 [[1],[2,3],[4,5,6]]——每层列表独立)。
- 锯齿断言(同树锯齿输出 [[1],[3,2],[4,5,6]]——方向标志)。
- 右视图断言(每层尾元素序列)。
- size 时机断言(故意把 size 放循环内,结果混层——穿帮对照)。
- 宽树断言(1 万节点全在左链:DFS 深度 1 万 vs BFS 队列峰值 1——形态差异实证,反例树形对照)。
- 预期:分层正确性与形态差异双证据。

### 第三步发散·发散要点 追问链:分层三刀

- **追问①**：层内排序键——按值排序/按进入序,业务树(部门排序)要显式键;
- **追问②**：层序与序列化——层序序列化保留空节点(第 40 题专用题),前序+null 也行,层序的好处=重建时直接对位;
- **追问③**：工程迁移——组织树渲染/评论楼中楼分页(按层)/依赖图分层调度(第 33 题拓扑+层=并行波次,Kahn 队列每轮就是一层)

## 总结点

1. size 快照在内循环前
2. 计数法优于哨兵法
3. 宽树 BFS 费内存,深树 DFS 费栈
