## 参考回答

<!-- explanation:deep -->

> 场景与约束：网银支付沙盘:支付渠道抽象——抽象类(PartialTemplate:通用流程骨架+子类实现细节)vs 接口(PaymentChannel:纯契约+default 方法提供默认行为)——两者的选择取决于"是否有共享状态与模板流程"。

1. 抽象类:单继承+可有构造器+可有实例字段+可有具体方法——表达"is-a"关系(部分实现);接口:多实现+无构造器+无实例字段(Java 8 后可有 default/static 方法)+字段默认 public static final——表达"can-do"能力(契约)。
2. Java 8 接口增强:default 方法(接口可提供默认实现——实现类可不覆写,解决"接口升级破坏实现类"问题)、static 方法(接口工厂/工具方法);Java 9 私有方法(default 方法间共享代码)——接口从"纯契约"进化为"含默认行为的契约"。
3. 选择判据:有共享状态+模板流程(子类复用骨架)→抽象类(模板方法模式);纯契约+多继承能力→接口(策略/回调/标记);Java 8 后接口的 default 方法覆盖了部分抽象类场景,但"需要实例字段和构造器"仍是抽象类的不可替代优势。

## 参考分析

### 第二步扩展① 机制:is-a 与 can-do 的语义差异

- 抽象类表达"是什么"(Bird is-an Animal——继承属性与行为)。
- 接口表达"能做什么"(Bird can-fly,Swimmer can-swim——实现能力契约)。
- 类比职业:抽象类是"科班出身"(有基础培训),接口是"资格证书"(证明有某种能力)——一个人可以多证(多实现),但只有一个科班(单继承)。

### 第二步扩展② 反例:抽象类与接口误用的两种事故

- 事故一:接口放实例字段——接口字段默认 public static final(常量),不是实例字段。
- 需要实例状态→用抽象类。
- 事故二:抽象类当接口用——抽象类所有方法抽象+无字段=功能上等同接口但限单继承。
- 修复=改接口(Java 8 后接口能力足够)。

### 第二步扩展③ 取舍:default 方法的使用边界

- default 方法的价值:接口演进(新增方法不破坏现有实现)+可选行为(实现类可选择覆写)。
- 风险:多实现的 default 冲突(类实现两个接口有同名 default 方法→必须覆写解决冲突)。
- 过度使用 default=接口变成抽象类(失去"纯契约"的清晰性)——default 适合"可选行为"与"接口演进",不适合核心逻辑。

## 案例

### 第三步发散·验证与推演 验证:抽象类与接口的走查核对

- 验证:单继承断言(类 extends 抽象类只能一个)。
- 多实现断言(implements 接口可多个)。
- default 方法断言(不覆写则用默认实现)。
- 冲突解决断言(两接口同名 default→实现类必须覆写)。
- 抽象类模板方法断言(骨架 final,子类实现步骤)。
- 验证:五组断言固化两者的语义边界。

### 第三步发散·追问扩展 追问链:继承三刀

- **Q1：接口的 static 方法?**
  - 答：接口 static 方法不可被实现类继承(须通过接口名调用)——与类的 static 方法(可继承)不同;适合接口级工具方法。
- **Q2：抽象类有构造器吗?**
  - 答：有(供子类 super() 调用初始化共享字段);接口无构造器(不能实例化)。
- **Q3：匿名类与 Lambda?**
  - 答：匿名类可实现接口或继承抽象类;Lambda 只能实现单方法接口(函数式接口)——Java 8 后 Lambda 替代大部分匿名类(简洁)。

## 总结点

1. 抽象类=模板+共享状态,单继承
2. 接口=契约+default,多实现
3. default 适合可选行为,不装核心逻辑
