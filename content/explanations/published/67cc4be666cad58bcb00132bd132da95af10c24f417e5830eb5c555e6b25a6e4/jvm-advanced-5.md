## 参考回答

<!-- explanation:deep -->

> 场景与约束：Java 17 G1 完成并发标记后进入 Mixed GC，但老年代持续升高，需要区分存活集增长和回收跟不上。

1. Mixed GC 会在年轻代回收基础上选择部分垃圾较多的 Old Region，不是一次清空老年代。
2. 同时看标记结果、候选 Region 存活量、回收速度、分配速率和回收后 live set。
3. 老年代增长先区分真实存活增长、标记太晚和回收能力不足，再逐项验证，不能只看峰值。

## 参考分析

### 选择逻辑

G1 根据垃圾比例、回收收益、暂停目标和复制成本选择部分 Old Region；存活对象多时单次回收收益和复制成本会同时变化。

回收集合还受可用 to-space 影响，Mixed 阶段可能分多轮推进，不能按一次回收推断整个老年代状态。类比打折清仓先清存货最多、效益最好的货架：G1 挑存活最少的 region 回收——mixed 只清一部分，不是全库大扫除。

### 增长曲线

若主要 GC 后 live set 阶梯上升，先查缓存和引用链；若 live set 稳定但峰值上升，更像分配速率或回收能力不足。

还要把应用对象统计、已提交堆和 RSS 分开看，三者增长不一定代表同一类问题。

### 调优边界

增加回收频率可能牺牲吞吐，增大堆可能延后故障并增加成本；要同时观察 Full GC、evacuation failure、p99 和错误率。

避免用吞吐下降或拒绝请求换取表面上的占用下降。

## 案例

### 曲线实验

固定负载，分别制造缓存存活增长和短命对象分配加速，记录 Old Region、live set、Mixed 回收量和分配速率，预期能区分两类问题。

再重复高峰和恢复阶段，结果应标注为目标 JDK 和负载下的实验。

### 回归验收

调整一个变量后比较 p99、GC CPU、Mixed 次数、Full GC、堆峰值和恢复速度，不以 Old 占用下降单独判定成功。

只有用户指标、GC 资源和恢复速度都没有恶化，才可保留新策略；预期是回收后存活集和 p99 在稳定窗口内收敛。

## 总结点

1. 清仓先清存货最少的货架
2. Mixed 只回收部分老年代
3. 看回收后存活集
4. 区分存活增长与跟不上
