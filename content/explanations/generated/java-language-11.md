## 参考回答

1. 受检异常要求调用方捕获或声明；RuntimeException 与 Error 属于非受检异常。
2. 边界按调用方能否合理恢复和 API 契约划分，不能只按“业务或技术异常”机械分类。
3. 跨层转换异常要保留 cause 和上下文，不应统一吞掉或改成无信息的成功结果。

## 参考分析

1. 受检异常把处理义务写进方法签名，但不能保证调用方确实恢复成功。
2. RuntimeException 不代表不处理；应在明确的应用边界统一转成错误响应。
3. 资源释放由 try-with-resources 等结构保障，不依赖异常被哪一层捕获。

## 案例

1. 场景（教学示例）：批量导入中，一条记录格式错误可以跳过，底层文件读失败则停止整批。

2. 处理：为可恢复的单条失败定义明确异常契约；底层 IOException 透传或保留 cause 转换，编程错误不上报成功。

3. 验证：坏记录有行号和失败原因；文件读失败不继续写入后续数据，调用方仍能追溯原始异常。

## 总结点

1. 异常边界看恢复契约。
2. 转换留根因，失败别吞掉。
